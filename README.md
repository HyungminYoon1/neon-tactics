# NEON TACTICS — 내일의 공격

세 기체의 이동·밀치기·끌기·교환으로 적의 공격선을 바꾸는 턴제 전술 게임입니다.

[게임](https://hyungminyoon1.github.io/neon-tactics/) · [WEB LAB](https://hyungminyoon1.github.io/web-lab/) · [소스](https://github.com/HyungminYoon1/neon-tactics)

## 임무와 조작

기존 도시 방어 12개(v1)를 보존하고 호송(13), 전원 탈출(14), 거점 유지(15), 최종 방어선(16)을 추가했습니다. 첫 방문에서 조작 입문 또는 최상위 임무를 선택할 수 있습니다. 입문은 실제 1번 임무를 플레이하며 도움 기록으로 분류합니다.

- 세 기체가 턴당 3명령을 공유합니다. 이동/기술 각각 1명령, 기체당 최대 2행동입니다.
- 1/2/3 기체 선택, Q 이동/E 기술, 방향키 목표, Enter 확인, Z 되돌리기, T 적 턴. 모바일 목표 패드도 같습니다.
- 전장 맞춤, 100–250% 확대/축소, 터치 스크롤·마우스 드래그·방향 버튼으로 이동합니다.
- 기술 미리보기는 이동·충돌·폭발·탈출을, 적 턴 예상은 공격 순서·피해·목표 진행·증원/종료 결과를 계산합니다.
- 호송차는 적 턴 뒤 인접한 생존 기체가 있으면 빈 다음 경로 칸으로 한 칸 전진합니다. 내구도는 3이며 직접 조종/교환할 수 없습니다.
- 탈출은 EXIT 칸에 진입한 기체가 전장을 떠납니다. 세 기체 모두 탈출해야 하며 하나라도 파괴되면 실패합니다.
- 거점 유지는 적 공격을 마친 시점의 점유로 계산하며, 점유가 끊기면 연속 횟수가 초기화됩니다.

16번은 5턴 안에 적 전멸, 시설 전력 12/12, 전원 생존, 기술 10회 이하, R 거점 4회 연속 유지를 요구합니다. 기존 마지막 임무의 배치·증원에 위치 유지와 자원 제약을 결합했습니다. 해답은 실제 모델 명령으로 검증했으며 사람의 난도·재미 평가는 별도입니다.

## 저장

연습과 입문의 진행·최고 기록을 이 기기에 자동 저장합니다. 저장 복원/기록 삭제는 하단에 있습니다. 독립 기록과 도움 사용 기록을 분리하며, 힌트 사용 표시는 되돌리기로 지워지지 않습니다.

`neon-tactics-save-v2`: schema 2, rules `neon-2.0.0`, 최대 128 KiB UTF-8. 현재 실행 1개와 임무별 독립/도움 최고 실행 각 1개, 실행당 입력 최대 128개, 되돌리기 32상태입니다. 명령 기록을 재실행하여 복원하며 저장된 점수나 상태 스냅샷을 신뢰하지 않습니다. 오래된 버전·손상·불법 명령은 거절합니다. 저장 실패 시 현재 탭에서 계속 플레이할 수 있습니다.

`web-lab-progress-v1`에는 실제로 저장된 독립 완료 개수/총수/갱신 시각만 공유합니다. 15개 앱 allowlist, 8 KiB, 완료 수 0..총수≤1000을 검증합니다. 이름·명령·개인 파일은 포함하지 않습니다. 삭제는 이 게임의 저장과 자체 요약만 제거합니다.

실명 계정·쿠키·분석·외부 자산은 없습니다. 일반 플레이는 서버에 전송하지 않습니다. 공개 기록 기능만 별도 API에 연결하며 호스팅 로그는 앱의 저장 기능과 별개입니다.

## 최상위 공개 기록

하단 **공개 기록 도전**은 16번 고정 조건을 새로 시작합니다. 힌트/되돌리기는 사용할 수 없으며 실시간 속도는 점수에 사용하지 않습니다. 완료 뒤 등록을 누르면 서버가 실제 명령을 다시 실행하여 최고 기록을 공개합니다. 자동 게시하지 않습니다. 임무 메뉴의 최상위 연습은 등록 없이 같은 조건을 연습합니다. 공개 도전은 메모리에 유지하며 연습 저장을 덮어쓰지 않습니다.

닉네임은 선택 사항입니다. 서버에는 익명 식별값·검증용 명령·최고 기록을 저장하며 마지막 활동 후 180일 보관합니다. 등록 권한은 이 브라우저의 별도 키에 저장됩니다. **공개 기록 삭제**는 이 익명 식별값으로 등록한 NEON TACTICS와 PARCEL PANIC의 공개 기록을 함께 삭제하며 기기 내 플레이 기록은 유지합니다. 브라우저 저장만 지우면 삭제 권한도 잃을 수 있습니다.

[랭킹 서버](https://github.com/HyungminYoon1/web-lab-ranking) · [API 상태](https://web-lab-ranking.hyeongmin92.workers.dev/health)

- `dist/src/ranked.js`: `RULES_VERSION`, `CHALLENGE_ID`, `rankingDefinition()`, `replayRanked(actions)`.
- 외부 명령은 `{type:"move"|"skill",unitId:"R"|"H"|"S",x:0..7,y:0..7}` 또는 `{type:"endTurn"}`. 최대 20개이며 다른 필드·명령·불법 행동을 거절합니다.
- 결과는 `{won,score,tieBreak,summary}`. 점수는 모델이 계산합니다. 동점 비교는 턴/명령/시설 손실/기체 손실 순으로 작은 값이 우선입니다. 시계·타임스탬프는 점수에 사용하지 않습니다.
- `dist/src/app.js`의 `rankingAdapter`: `start()`, `getActions()`, `isComplete()`, `getDefinition()`. 실제 입력만 캡처하고 `ranking-client.js`가 명시적 API 조작을 담당합니다.
- API 이외 연결은 CSP로 차단합니다. 서버 명령 재검증은 사람만 플레이했거나 한 사람당 한 계정이라는 보장은 아닙니다.

## 실행과 검증

Node.js 22 이상, 설치할 패키지 없음.

```sh
npm run dev -- 0
npm test
npm run check
```

로컬 모델/저장/순위 테스트 44개가 통과했습니다. 기존 12개 해답과 점수, 새 4개 목표의 합법 해답·실패, 명령/적 턴 미리보기, 저장 재실행·오염/크기/버전 경계, 도움 분리, 실제 독립 완료 요약, 순위 입력 검증을 포함합니다.

현재 수정본의 브라우저 E2E/스크린샷, 원격 CI, 공개 배포는 메인 작업의 검증 대상입니다. 이전 브라우저 기록은 이번 수정본의 증거로 사용하지 않습니다. 실제 화면 캡처 절차와 해답은 [검증 기록](docs/verification.md)을 참고하세요.
